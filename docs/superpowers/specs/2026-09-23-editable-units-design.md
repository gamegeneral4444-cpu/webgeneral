# ย้ายกลุ่มงานเข้าฐานข้อมูล ให้เพิ่ม/ลบ/แก้เองได้

วันที่ 2026-09-23 · แบรนช์ `codex/initial-website`

## เหตุผล

ผู้ใช้จะไม่ได้ดูแลเว็บนี้ตลอดไป ระบบต้องอยู่ได้โดยไม่ต้องพึ่งคนเขียนโค้ด
ตอนนี้รายชื่อ 14 กลุ่มงานฝังอยู่ใน `lib/units.ts` เพิ่ม/ลบต้องแก้โค้ดแล้ว deploy

## ของที่มีอยู่แล้วและใช้ซ้ำได้

- `components/lucide-icon.tsx` แสดงไอคอนจากชื่อที่เก็บเป็นข้อความ เช่น `"Building2"`
  เมนู "ระบบบริการ" ใช้วิธีนี้อยู่แล้ว จึงไม่ต้องคิดใหม่
- ตาราง `unit_details` ที่เพิ่งทำ เก็บคำอธิบาย — จะถูกยุบรวมเข้าตารางใหม่

## โครงสร้างข้อมูล

ตารางเดียวจบ `public.units`

| คอลัมน์ | ชนิด | หมายเหตุ |
|---|---|---|
| `slug` | text PK | ตัวเชื่อมกับ `unit_posts` และ `unit_staff` **ห้ามแก้หลังมีข้อมูล** |
| `label` | text | ชื่อที่แสดง แก้ได้ตลอด |
| `icon` | text | ชื่อไอคอน Lucide เช่น `Building2` |
| `description` | text | หน้าที่และความรับผิดชอบ |
| `sort_order` | int | ลำดับการแสดง |
| `is_active` | boolean | ปิด = ซ่อนจากเว็บสาธารณะ ข้อมูลยังอยู่ |

RLS: ใครก็อ่านได้เฉพาะ `is_active` · เพิ่ม/แก้/ลบเฉพาะ `super_admin`, `admin`

## กติกาที่ตั้งใจออกแบบ

1. **ลบ = ซ่อน ไม่ใช่ลบจริง** กันข้อมูลกำพร้า เพราะ `unit_posts` กับ `unit_staff`
   อ้างงานด้วย `slug` แต่ไม่มี foreign key (ตอนออกแบบแรกงานอยู่ในโค้ด)
2. **ลบถาวรได้เฉพาะงานที่ไม่มีโพสต์และไม่มีผู้รับผิดชอบ** ถ้ามี ระบบบอกจำนวนแล้วไม่ให้ลบ
3. **`slug` แก้ไม่ได้หลังสร้าง** ล็อกในฟอร์ม ถ้าจะเปลี่ยนต้องสร้างใหม่แล้วย้ายข้อมูลเอง
4. **รายชื่อในโค้ดยังอยู่เป็นค่าสำรอง** ถ้าตารางยังไม่ถูกสร้างหรือต่อฐานข้อมูลไม่ได้
   เว็บจะใช้ 14 งานเดิมจากโค้ด จึง deploy ก่อนรัน SQL ได้โดยไม่พัง

## ผลกระทบต่อโค้ด

`Unit.icon` เปลี่ยนจากคอมโพเนนต์ React เป็น **ชื่อไอคอนแบบข้อความ** ทุกที่ที่เคยเรียก
`<u.icon />` ต้องเปลี่ยนเป็น `<LucideIcon name={u.icon} />`

คอมโพเนนต์ฝั่ง client 3 ตัวเคย import `UNITS` ตรง ๆ ต้องเปลี่ยนเป็นรับผ่าน props
เพราะดึงฐานข้อมูลฝั่ง client ไม่ได้

| ไฟล์ | ฝั่ง | ทำอะไร |
|---|---|---|
| `components/public/units-nav.tsx` | client | รับ `units` เป็น prop จาก `site-header` ซึ่งรับต่อจาก `layout` |
| `app/admin/unit-posts/unit-post-form.tsx` | client | รับ `units` จากหน้า create/edit |
| `app/admin/staff/staff-form.tsx` | client | รับ `units` จากหน้า create/edit |

`unitPostSchema` เดิมตรวจว่า `unit_slug` อยู่ในรายการโดย import `UNITS`
เปลี่ยนเป็นตรวจแค่รูปแบบข้อความ แล้วไปตรวจว่ามีงานนี้จริงใน server action แทน
(schema ถูก import ฝั่ง client จึงพึ่งฐานข้อมูลไม่ได้)

## หน้าแอดมินใหม่

`/admin/units` แทนที่ `/admin/unit-details` เดิม — ตารางรายการงาน + เพิ่ม/แก้/ซ่อน/เรียงลำดับ
ฟอร์มมี: ชื่อ · รหัส (ล็อกเมื่อแก้) · ไอคอน · คำอธิบาย · ลำดับ · เปิด/ปิดการแสดง

## นอกขอบเขต

- ไม่ทำตัวเลือกไอคอนแบบมีภาพให้เลือกทั้งหมด (Lucide มีเป็นพัน) ใช้ช่องพิมพ์ชื่อ
  พร้อมแสดงตัวอย่างไอคอนสดและลิงก์ไปเว็บ lucide.dev
- ไม่ย้าย `unit_posts.unit_slug` ไปเป็น foreign key ของ `units`
  เพราะจะทำให้ลบงานแล้วโพสต์หายตามโดยไม่ตั้งใจ ใช้กติกาข้อ 2 คุมแทน
